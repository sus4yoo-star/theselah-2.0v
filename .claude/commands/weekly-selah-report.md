# SELAH 주간 점검 리포트 생성

theselah-2.0v 저장소를 점검하고 비개발자가 이해할 수 있는 한국어 주간 리포트를
작성한 뒤 PR로 올린다. **코드는 절대 수정하지 않는다 — 리포트(문서)만 추가한다.**

## 절차

1. **브랜치**: `main` 최신 상태를 받아 그 기준으로 새 작업 브랜치를 만든다.
   브랜치명 예: `claude/weekly-report-<YYYY-MM-DD>`.
   **`main`에 직접 커밋하지 않는다.**

2. **점검**: 다음을 코드 직접 검토로 훑는다.
   - 서버 API (채팅 `/api/chat`, 알림 `/api/reminders`, 푸시 `/api/push/*`, 크론 `/api/cron/*`)
   - 인증·미들웨어 (`src/lib/supabase/*`, `src/middleware.ts`)
   - 데이터베이스 설정 (`supabase/**/*.sql`) — RLS 정책 포함
   - 서비스워커 / PWA (`public/sw.js`, `public/manifest.json`)
   - 주요 라이브러리 (`src/lib/*`)
   - 배포·환경 설정 문서 (`README*.md`, `next.config.mjs`, `netlify.toml`)
   점검 관점: **새 버그 · 미완성 · 개선점 · 보안 이슈.**

3. **제안**: 출시/운영 관점에서 "다음에 하면 좋을 일"을 **우선순위(1순위/2순위/3순위)**로 정리한다.

4. **저장**: 결과를 `reports/weekly-<YYYY-MM-DD>.md`에 저장한다.
   날짜는 실행일(GMT+9, 월요일) 기준. 비개발자도 이해하도록 쉬운 한국어로,
   각 항목에 **무엇이 문제인지 / 왜 중요한지 / 무엇을 하면 되는지**를 함께 적는다.
   심각도 표시(🔴 긴급 / 🟠 높음 / 🟡 보통 / 🟢 낮음)를 사용한다.

5. **PR**: 리포트 파일만 커밋·푸시하고 PR을 생성한다.
   - PR 제목 예: `docs: 주간 점검 리포트 추가 (<YYYY-MM-DD>)`
   - **코드 변경은 포함하지 않는다.** 리포트가 짚은 문제를 이번 PR에서 고치지 않는다.
   - PR 본문에 핵심 발견 사항을 우선순위와 함께 요약한다.

## 주의

- 직전 주 리포트(`reports/weekly-*.md`)가 있으면 먼저 읽어, 지난주 대비 **변화/해결/신규**
  항목을 구분해 적으면 더 유용하다.
- 리포트는 진단·제안용이다. 실제 코드 수정은 사용자가 별도로 요청할 때만 진행한다.
