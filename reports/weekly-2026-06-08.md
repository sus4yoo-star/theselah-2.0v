## 발견 사항

### 🟠 높음

---

#### 1. 기도 알림 메시지가 한국어·영어만 지원됨 (신규)

**무엇이 문제인가요?**
앱은 30개 언어를 지원하는데, 기도 알림 푸시 메시지는 사용자 언어가 영어(`en`)이면 영어, 그 외에는 모두 한국어로 전송됩니다. 태국어, 힌디어, 스페인어, 포르투갈어 등 28개 언어 사용자는 자신이 이해하지 못하는 한국어 알림을 받게 됩니다.

**왜 중요한가요?**
기도 알림은 사용자가 매일 기대하는 핵심 기능입니다. 알 수 없는 언어로 알림이 오면 사용자가 앱을 불신하거나 알림을 꺼버릴 수 있습니다. 글로벌 앱임을 감안하면 첫인상에 큰 영향을 줍니다.

**무엇을 하면 되나요?**
기도 알림 기본 메시지를 사용자 언어(`r.lang`) 기준으로 분기하거나, 대표 언어 그룹(한국어, 영어, 스페인어, 포르투갈어, 태국어 등)별 기본 문구를 준비합니다. 사용자가 직접 메시지를 입력하면 그대로 사용하므로, 기본값만 다국어로 보완하면 됩니다.

### 🟡 보통

---

#### 2. 속도 제한이 서버 한 대에서만 작동 (신규)

**무엇이 문제인가요?**
지난주 해결된 API 속도 제한은 서버 메모리에 저장됩니다. Netlify 같은 클라우드 서비스에서는 요청마다 다른 서버 인스턴스가 처리할 수 있기 때문에, 실제 제한 효과가 설정값보다 인스턴스 수배 만큼 느슨해질 수 있습니다. 코드 주석에도 이 한계가 명시되어 있습니다.

**왜 중요한가요?**
서버가 10개 인스턴스로 확장되면, 1분 20회 제한이 사실상 200회까지 허용될 수 있습니다. API 비용 방어 목적의 제한이 제대로 작동하지 않을 수 있습니다.

**무엇을 하면 되나요?**
현재 설정도 전혀 없는 것보다 훨씬 낫습니다. 향후 트래픽이 늘면 Upstash(Redis) 같은 공유 저장소 기반 속도 제한으로 교체하면 됩니다. 당장 급하지는 않으나 성장 계획 시 고려하세요.

---

#### 3. 푸시 알림 테스트 버튼에 횟수 제한 없음 (신규)

**무엇이 문제인가요?**
설정 화면의 "테스트 알림 보내기" 버튼(`/api/push/test`)은 횟수 제한 없이 클릭할 때마다 즉시 푸시를 발송합니다. 채팅 API와 달리 이 엔드포인트에는 속도 제한이 적용되지 않습니다.

**왜 중요한가요?**
악의적인 사용자나 버그로 인해 반복 클릭이 발생하면, 해당 사용자의 모든 기기에 대량의 테스트 알림이 발송될 수 있습니다. 웹 푸시 발송 서비스(web-push)에 과부하를 줄 수도 있습니다.

**무엇을 하면 되나요?**
테스트 알림 API에도 속도 제한을 적용합니다. 예를 들어 1시간에 3회 이하로 제한하면 충분합니다.

---

#### 4. 오류가 발생해도 개발팀이 알 수 없음 (미해결)

**무엇이 문제인가요?**
AI 메모리 저장, 데이터베이스 처리, 스트리밍 응답 중 오류가 발생해도 조용히 넘어가며 서버 로그에만 기록됩니다. 별도의 오류 수집·알림 체계가 없습니다.

**왜 중요한가요?**
사용자는 문제를 경험하고 있는데 운영팀이 알지 못하는 상황이 생길 수 있습니다. 특히 메모리 저장 실패가 반복되면 사용자 맥락이 쌓이지 않아 앱 품질이 서서히 저하될 수 있습니다.

**무엇을 하면 되나요?**
Sentry (무료 플랜 있음) 같은 오류 수집 서비스를 연결합니다. 최소한 중요한 오류가 발생하면 이메일로 알림을 받도록 설정합니다.

---

#### 5. 위기 상황 전화번호가 한국·영어권만 제공됨 (미해결)

**무엇이 문제인가요?**
자살·자해 등의 위기 상황은 30개 언어 모두에서 정확하게 감지됩니다. 하지만 실제 긴급 연락처 안내는 한국어(자살예방상담전화 1393)와 영어(1-800-273-8255)만 제공됩니다.

**왜 중요한가요?**
위기 상황에서 정확한 현지 상담 전화번호를 알지 못하면, 사용자가 즉각적인 도움을 받지 못할 수 있습니다. 이는 생명과 직결된 문제입니다.

**무엇을 하면 되나요?**
주요 지원 언어(스페인어, 포르투갈어, 태국어, 힌디어 등)별 국가 위기 상담 전화번호를 추가합니다. 국제 생명의전화(Befrienders Worldwide) 웹사이트에서 국가별 번호를 확인할 수 있습니다.

---

#### 6. 자동 삭제 설정이 기기 간 동기화되지 않음 (신규)

**무엇이 문제인가요?**
대화 자동 삭제 설정(30일/90일/사용 안 함)이 현재 사용 중인 기기의 로컬 저장소(localStorage)에만 저장됩니다. 스마트폰에서 설정해도 컴퓨터에서는 반영되지 않으며, 브라우저 데이터를 지우면 설정이 초기화됩니다.

**왜 중요한가요?**
사용자가 개인정보 보호를 위해 자동 삭제를 설정했는데, 다른 기기에서는 대화가 영구 보관될 수 있습니다. 의도와 다른 결과가 나와 사용자가 혼란을 겪을 수 있습니다.

**무엇을 하면 되나요?**
자동 삭제 설정을 데이터베이스(profiles 테이블)에 저장해 모든 기기에서 동일하게 적용되도록 합니다.

#### 10. 메모리 갱신에 비용이 큰 모델 사용 (미해결)

**무엇이 문제인가요?**

**왜 중요한가요?**

**무엇을 하면 되나요?**
메모리 갱신 호출에는 경량 모델(예: claude-haiku-4-5)을 사용하도록 분리합니다.

## 이번 주 긍정적 발견사항

이번 주에 새로 추가된 코드(`rate-limit.ts`, `anthropic.test.ts`, `selah-memory.test.ts`, `rate-limit.test.ts`)는 앱 품질 관리 체계가 강화되고 있음을 보여줍니다. 특히:

- **테스트 코드 도입**: 핵심 기능(속도 제한, 메모리, Anthropic 연동)에 자동 테스트가 추가되어 앞으로 실수를 미리 잡을 수 있게 됨
- **CI 파이프라인 구축**: `.github/workflows/ci.yml`이 새로 추가되어 코드 변경마다 자동 검증이 실행됨
- **위기 감지 커버리지**: `crisis-detect.ts`가 30개 언어 전체에서 자살·자해·폭력 키워드를 정확히 감지하는 탄탄한 구현
- **서비스워커 안정성**: v6에서 PWA 설치 관련 파일을 항상 네트워크에서 받도록 개선, iOS 설치 문제 방지
- **권한 최소화 원칙 준수**: Cron 작업은 서비스 롤 키를 사용하지만, 일반 API는 RLS가 적용된 일반 클라이언트를 사용
