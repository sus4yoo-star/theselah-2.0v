## 점검 범위

이번 주에 살펴본 항목:

- **채팅 API** (`/api/chat`): Claude와 실시간 대화하는 핵심 기능
- **기도 알림 API** (`/api/reminders`, `/api/cron/send-reminders`): 매일 정해진 시간에 알림 발송
- **푸시 알림 API** (`/api/push/*`): 기기에 알림 보내는 기능
- **로그인·인증** (`middleware.ts`, `supabase/`): 사용자 계정 보호
- **데이터베이스 보안** (`supabase/*.sql`): 행 수준 보안 정책
- **서비스워커·PWA** (`public/sw.js`, `manifest.json`): 오프라인 및 앱 설치
- **배포 설정** (`next.config.mjs`, `netlify.toml`, `README_DEPLOY.md`)

## 발견 사항

### 🟠 높음

---

#### 1. API 요청 횟수 제한이 없음

**무엇이 문제인가요?**  
누구든 로그인만 하면 채팅 버튼을 무한정 클릭할 수 있고, 클릭할 때마다 Claude API 비용이 발생합니다. 현재 하루에 몇 번 호출하든 제한이 없습니다.

**왜 중요한가요?**  
Claude API는 사용량만큼 비용이 청구됩니다. 이상한 스크립트나 악의적인 사용자가 짧은 시간에 수천 번 호출하면 예상치 못한 큰 청구서가 날아올 수 있습니다.

**무엇을 하면 되나요?**  
사용자 1명이 하루에 보낼 수 있는 메시지 수에 상한선을 두거나 (예: 1일 50회), 짧은 시간 내 연속 호출을 차단하는 "속도 제한(Rate Limit)" 기능을 추가합니다.

---

#### 2. 이미지 업로드 크기 제한이 없음

**무엇이 문제인가요?**  
채팅에 이미지를 첨부할 수 있는데, 매우 큰 이미지(수십 MB)를 보내도 서버가 그대로 받아서 처리합니다. 이미지는 텍스트로 변환(base64 인코딩)되어 API에 전달되므로, 원본보다 더 커집니다.

**왜 중요한가요?**  
서버 메모리가 부족해질 수 있고, 여러 명이 동시에 큰 이미지를 보낼 경우 서버가 멈출 수 있습니다.

**무엇을 하면 되나요?**  
이미지를 받기 전에 크기를 확인하여 예컨대 5MB 이상이면 거부하고 사용자에게 안내 메시지를 보냅니다.

---

### 🟡 보통

---

#### 3. 오류가 나도 개발팀이 알 수 없음

**무엇이 문제인가요?**  
사용자 개인 메모리(이전 대화 맥락)를 저장하거나 불러오는 중 오류가 발생해도, 시스템이 조용히 무시하고 진행합니다. 오류를 기록하거나 알림을 보내는 체계가 없습니다.

**왜 중요한가요?**  
"메모리 저장 실패"가 반복되고 있어도 운영자가 모르기 때문에, 사용자들이 이전 대화를 기억하지 못하는 앱을 계속 쓰게 될 수 있습니다. 문제를 뒤늦게 발견하면 수정도 늦어집니다.

**무엇을 하면 되나요?**  
Sentry, Datadog, 또는 간단한 이메일 알림과 같은 오류 추적 시스템을 연결합니다. 최소한 서버 로그에 오류 내용이 남아야 합니다.

---

#### 4. 위기 상황 전화번호가 한국·영어권만 제공됨

**무엇이 문제인가요?**  
앱이 30개 언어를 지원하는 글로벌 앱이지만, 자살·위기 상황 감지 후 안내하는 전화번호는 한국과 영어권(1-800-273-8255) 두 곳만 준비되어 있습니다.

**왜 중요한가요?**  
일본어, 스페인어, 포르투갈어 등 다른 언어 사용자가 위기 상황에 처했을 때 해당 국가의 긴급 연락처를 안내받지 못할 수 있습니다. 이는 생명과 직결되는 기능입니다.

**무엇을 하면 되나요?**  
각 지원 언어에 맞는 국가별 위기 상담 전화번호를 추가합니다. 국제 생명의전화(Befrienders Worldwide) 등의 리소스를 활용할 수 있습니다.

---

#### 5. 데이터베이스 마이그레이션 수동 실행 필요

**무엇이 문제인가요?**  
새 서버에 앱을 배포할 때 필요한 데이터베이스 테이블(특히 사용자 메모리 테이블)을 관리자가 직접 SQL을 실행해서 만들어야 합니다. 자동화가 되어 있지 않습니다.

**왜 중요한가요?**  
새 환경에 배포할 때 이 단계를 빠뜨리면 메모리 기능이 조용히 작동하지 않습니다. 사용자는 앱을 쓸 수는 있지만, 대화 내용을 기억하지 못하는 앱을 경험하게 됩니다.

**무엇을 하면 되나요?**  
배포 체크리스트에 명확히 명시하고, 가능하다면 배포 스크립트에서 자동으로 마이그레이션을 실행하도록 구성합니다.

---

#### 6. 일부 배포 문서가 이전 버전 내용을 참조

**무엇이 문제인가요?**  
`SELAH_2_1_PRAYER_PATCH_NOTE.md` 파일에 `OPENAI_MODEL`이라는 환경 변수가 언급되어 있습니다. 하지만 현재 앱은 OpenAI가 아닌 Anthropic(Claude)을 사용하며, 실제 변수명은 `ANTHROPIC_MODEL`입니다.

**왜 중요한가요?**  
신규 개발자나 운영자가 이 문서를 보고 잘못된 설정을 할 수 있습니다. 특히 처음 서버를 설정하는 사람이 혼란을 겪을 수 있습니다.

**무엇을 하면 되나요?**  
해당 문서의 `OPENAI_MODEL` 부분을 `ANTHROPIC_MODEL`로 수정하고, 구버전 참조를 제거합니다.

### 🟢 낮음

---

#### 7. PWA 앱 설치 화면 최적화 미흡

**무엇이 문제인가요?**  
앱을 스마트폰 홈화면에 설치할 때 표시되는 미리보기 화면(스크린샷)이 `manifest.json`에 등록되어 있지 않습니다. iOS 16 이상에서는 설치 전에 앱 화면을 미리 보여주는 기능이 있는데 활용되지 않습니다.

**왜 중요한가요?**  
설치 화면에서 앱의 실제 모습을 보여주면 설치 전환율이 높아집니다. 반대로 미리보기가 없으면 사용자가 설치를 망설일 수 있습니다.

**무엇을 하면 되나요?**  
앱 주요 화면 2~3개를 캡처한 스크린샷을 `manifest.json`의 `screenshots` 항목에 추가합니다.

---

#### 8. Cron 작업 모니터링 부재

**무엇이 문제인가요?**  
기도 알림을 보내는 자동 작업(Cron)이 실패해도 개발팀이 알 수 없습니다. 예를 들어 Netlify Cron이 잠시 멈추거나, 알림 발송 서버에 문제가 생겨도 조용히 지나갑니다.

**왜 중요한가요?**  
사용자가 매일 기대하는 기도 알림을 며칠 동안 받지 못해도 개발팀이 먼저 인지하기 어렵습니다.

**무엇을 하면 되나요?**  
Cron 작업의 성공/실패 횟수를 기록하고, 연속 실패 시 이메일 또는 슬랙으로 알림을 받도록 설정합니다. (예: Better Uptime, Cronitor 등 무료 모니터링 서비스 활용)

---

#### 9. 메모리 갱신에 비용이 큰 모델 사용

**무엇이 문제인가요?**  
채팅 1회마다 Claude API가 두 번 호출됩니다. 첫 번째는 실제 대화 응답, 두 번째는 이전 대화 내용을 요약·저장하는 메모리 업데이트입니다. 두 번 다 같은 고사양 모델(claude-sonnet-4-6)을 사용합니다.

**왜 중요한가요?**  
메모리 업데이트는 단순한 요약 작업이므로 더 저렴한 모델(예: claude-haiku-4-5)로 충분합니다. 현재 구조는 필요 이상의 비용이 발생합니다.

**무엇을 하면 되나요?**  
메모리 갱신 호출에만 경량 모델을 사용하도록 분리합니다. 대화 품질은 그대로이면서 API 비용을 약 30~50% 절감할 수 있습니다.

## 이번 주 긍정적 발견사항

앱의 전반적인 품질은 높습니다. 특히 다음 항목은 잘 갖춰져 있습니다:

- **보안**: Claude API 키가 서버에만 저장되어 외부 유출 위험 없음
- **사용자 데이터 격리**: Supabase RLS 정책으로 내 데이터는 나만 볼 수 있음
- **30개 언어 지원**: 각 언어별 성경 번역본(한국어 개역개정, 영어 NIV 등)이 명확히 지정됨
- **이중 로그인 방식**: 웹(쿠키)과 모바일 앱(토큰) 모두 안전하게 지원
- **기도 알림 안전 처리**: 발송 실패한 기기 주소는 자동으로 정리됨
- **개인정보 보호**: AI 메모리에 비밀번호, 주소, 결제 정보가 저장되지 않도록 설계됨
